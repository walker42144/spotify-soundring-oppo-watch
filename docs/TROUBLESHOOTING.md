# 故障排查

| 现象 | 处理 |
| --- | --- |
| ADB 列表为空 | 检查 USB 调试、数据线、驱动和手表是否有数据连接；充电成功不等于调试成功 |
| unauthorized | 在手表确认当前电脑的调试授权 |
| 配对提示多台设备 | 断开其他调试手机，工具要求仅一台 device |
| 配对码不显示输入 | 隐藏输入是正常设计；直接输入数字后回车 |
| 配对码过期/403 | 在手表重新打开电脑配对，使用新码，不重复用旧会话 |
| INVALID_CLIENT / 回调不匹配 | 检查 Client ID 与 `http://127.0.0.1:8765/callback`，保存开发者应用设置 |
| 端口 8765 占用 | 关闭此前未退出的配置工具或占用此端口的程序，再重新开始；不要任意改回调端口 |
| 开发者应用无法创建/账号无权使用 | 查看 Spotify Dashboard 当前准入、Premium 和开发模式用户管理规则 |
| 没有活跃设备 | 相同账号在手机/电脑打开 Spotify 并开始播放，再刷新；手表本身不是 Spotify 播放设备 |
| 403 控制失败 | 查看具体提示：可能是设备限制、动作不支持或授权不足，不能仅据 403 判定没有会员；刷新后选择可控制设备 |
| 别人的歌单不可读 | 开发模式对歌单内容有权限边界，优先选择自己拥有或协作的歌单，不代表空歌单 |
| 音量灰色 | 当前设备未开放远程音量或被限制；不强行提交 |
| 429 | 接口限流，遵守等待时间，不连续点刷新；可用省电同步模式 |
| 502/503/504 | 服务端或上游临时故障；读取有限重试并退避，控制结果可能不明确，先刷新确认再操作 |
| 超时/离线 | 分别检查手表网络与电脑授权网络；本项目不配置 VPN、代理或系统网络；短时故障保留旧状态并显示同步时间 |
| 手机已切歌，手表稍后更新 | Web API 轮询和服务端传播存在延迟；快速模式约每秒发起读取，不是实时推送 |
| 连续点按没执行多次 | 控制串行处理且忙碌时抑制重复提交，避免多次切歌；等待状态更新再操作 |
| INSTALL_FAILED_UPDATE_INCOMPATIBLE | 签名与已安装版本不同；使用原签名来源更新。若决定卸载再装，先接受会丢失本地授权并需重新配对 |
| 图标仍是旧版 | 系统启动器可能缓存，先退出应用列表再进入；不要清除应用数据来刷新图标 |
| Python / cryptography 安装失败 | 检查 Python 版本、电脑网络及 pip 输出，重新运行 Setup.ps1；不需要在全局安装依赖 |

提交 issue 时仅提供：应用版本、通用型号、系统/API 版本、操作步骤、错误码和是否可复现。不要提供 Client Secret、令牌、完整回调 URL、配对码、序列号、IP、账号邮件或未遮挡的个人播放截图。
